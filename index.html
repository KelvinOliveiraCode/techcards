A virada

O app é o começo. O projeto é o produto.

Um trabalho acadêmico entregue no fim do semestre morre no fim do semestre. A ambição é fazer dele uma estrutura que continue viva depois que a nota sair.

Open source de verdade

Todo o código no GitHub: arquitetura em camadas, schema do banco, seeds e testes. Não um JAR fechado — a estrutura inteira, legível e forkável.

Polido, não funcional

Hoje a interface funciona. O passo seguinte é a interface de um produto: microinterações consistentes, responsividade, wizard de primeiro uso e acessibilidade de verdade.

Além dos cards padrão

Hoje o formato de estudo é o card. Amanhã a escolha é sua. Quiz, timer, modo prova, estudo em grupo, gerador automático a partir de PDF.

Um MCP, não só um app

Transformar o banco em superfície de que agentes e humanos mexem: consultar desempenho, gerar decks e automatizar estudo pelo mesmo protocolo.

Visão · a peça ambiciosa

O mesmo protocolo, para agentes e para gente

Um Model Context Protocol sobre o banco de estudos: a mesma superfície que um agente usa para automatizar é a mesma que você usa para estudar.

Um agente pode

listar decks criar cards registrar sessão consultar desempenho gerar quiz por tema exportar histórico

A ideia concreta: você pede ao agente “monte um quiz de deadlock com meus erros”, ele lê o histórico, monta a sessão e grava o resultado de volta no mesmo banco. O app mostra tudo na tela.

E você pode

brincar com o banco ver os próprios números automatizar backup gerar material novo

“MCP” costuma soar como coisa de servidor. Aqui é o contrário: é o SQLite local virando protocolo. Sem nuvem, sem conta, sem Give your data away. O playground é o seu banco.

Por que isso importa para o curso. Construir um servidor MCP exige projeto, protocolo, tratamento de erro e documentação — as mesmas competências pedidas nas disciplinas que o app estuda. O software deixa de ser o fim e passa a ser o campo de treino.
